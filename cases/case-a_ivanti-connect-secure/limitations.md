# Limitations (Case A)

## Limitations of this analysis
This case is based on **public, official sources only**, therefore:
- it cannot confirm compromise in any specific environment
- it cannot provide an internal timeline for any organization
- it cannot support attribution of threat actors with high confidence

## What would increase confidence (in a real SOC)
To move from “risk assessment” to “confirmed incident / ruled out”, a SOC would need:
- asset inventory & exposure confirmation
- patch/mitigation state verification
- gateway audit/log data (vendor-specific)
- correlated authentication and network telemetry
- post-remediation validation evidence

## Scope guardrails
No exploit testing and no offensive procedures are included.  
The purpose is to demonstrate **vulnerability triage, prioritization, and defensible documentation**.
